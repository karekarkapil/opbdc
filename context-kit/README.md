# The context kit

*Companion to Chapter 3, "Context Is the Company", of* 1 Person, Billion Dollar Conglomerate *(2026 edition). Last reviewed: September 2026.*

## What this is

An agent starts every task knowing a great deal about the world and almost nothing about your company. Its usefulness is capped by the context you give it. The context kit is that context, written down: ten short, plain, dated files that give an agent what a thoughtful new employee would learn in their first month.

Your company is a set of files. Keep them in one folder, in plain Markdown, so they work with every agent tool available today and with whatever appears next year.

## How to use it

1. Copy the ten templates below into a folder for your company (a shared drive, or a repository if you use version control).
2. Write the **company brief** and the **facts sheet** first. These two alone change the quality of everything your agents produce.
3. Start the **customer file** from your last month of emails, messages and calls.
4. Fill in the rest as you go. A file with three true lines beats a file with thirty guessed ones.
5. Point every brief at the files it needs (see [`../briefs/brief-template.md`](../briefs/brief-template.md)).
6. Put a monthly context review on your calendar (checklist below).

Two filled-in examples show what "done" looks like:

- [`examples/beverage-company/`](examples/beverage-company/): Copper Pot Mixers, a small company selling craft cocktail mixers to bars and cafes.
- [`examples/software-company/`](examples/software-company/): Ledgerly, a small bookkeeping-software company.

Both are fictional companies used for illustration.

## The ten files

| # | File | What it holds | Who reads it | Review |
|---|---|---|---|---|
| 1 | [`company-brief.md`](company-brief.md) | One page: what the company does, for whom, why, how it makes money, and what it does not do | Every agent, at the start of most tasks | Quarterly |
| 2 | [`customer-file.md`](customer-file.md) | Customers in their own words: verbatim, dated quotes from conversations, reviews, complaints, tickets | Research, product, marketing, sales and support agents | Add to it the day you learn something; skim monthly |
| 3 | [`facts-sheet.md`](facts-sheet.md) | The single source of truth for anything an agent might state to a customer: prices, packs, delivery, returns, contacts | Every customer-facing agent; anyone writing copy | Monthly, and first whenever a fact changes |
| 4 | [`specifications.md`](specifications.md) | An index of product and feature specs, each a one-page spec in nine parts | Coding, design and support agents | With every product change |
| 5 | [`voice-guide.md`](voice-guide.md) | How the company sounds: principles, replies you love, replies you hate, and why; your disclosure policy | Marketing, support and sales agents | Every time you reject a draft; quarterly |
| 6 | [`decision-log.md`](decision-log.md) | Each meaningful decision, its date and its reason | Every agent before changing anything settled; you | Monthly |
| 7 | [`glossary.md`](glossary.md) | Every term with a special meaning in your company or industry | Every agent | When a new term appears |
| 8 | [`playbooks.md`](playbooks.md) | An index of written procedures for recurring jobs, which become skills agents load on demand | The agent doing that job | After each use that taught you something |
| 9 | [`agent-instructions.md`](agent-instructions.md) | Standing rules for one place agents work: where things are, always, never, when to ask | Read automatically at the start of every task | Weekly, in the operating review |
| 10 | [`lessons-log.md`](lessons-log.md) | What went wrong, what you learned, what changed | You; agents when a similar job comes up | Weekly |

Plus one more file that grows out of the brand and voice guide:

- [`design-system.md`](design-system.md) (Chapter 8): the six parts every screen, page, email and image is built from, with a filled-in example for a small beverage brand.

## The seven principles of writing context

Use this as a checklist when you write or review any file in the kit.

- [ ] **Written for a smart new hire on their first day.** Assumes intelligence and no background. Explains why, not just what.
- [ ] **One source of truth per fact.** Each fact is written once; every other file points to it.
- [ ] **Standing instructions are short.** The always-read file fits on one or two pages; detail lives in playbooks that load on demand.
- [ ] **Shows, doesn't describe.** Examples of right and wrong, not adjectives.
- [ ] **Says what not to do.** The boundaries are written down.
- [ ] **Dated.** Every file has a "Last checked" date at the top. Anything older than a quarter is suspect.
- [ ] **Written where you work.** Captured at the moment of learning, not "later".

## Memory: the rule

**Let agents remember working details; make the company's truths a matter of record.**

Agent memory is a notebook, not a record. What an agent remembers is what it decided was worth remembering, in its own words, and it can be wrong, stale or manipulated. When an agent's memory holds something important, promote it into the right file here, reviewed and dated. Delete anything wrong or unexpected.

## Monthly context review (30 minutes)

- [ ] Read the facts sheet line by line. Is every price, date and policy still true?
- [ ] Check every file's "Last checked" date. Anything older than three months gets read and re-dated or fixed.
- [ ] Look for contradictions: does any fact appear in more than one file? Keep it in one, point to it from the others.
- [ ] Read what your main agents have remembered. Promote what is true into the kit; delete what is wrong.
- [ ] Read the decision log. Does any reason no longer hold? If so, reopen the decision deliberately.
- [ ] Read the lessons log. Has each lesson become a rule in the right file?
- [ ] Check the agent instruction files are still one to two pages. Move detail into playbooks.
- [ ] Search for secrets: no passwords, keys, card numbers or personal data in any file agents read.

## Carrying the kit to your next company

Chapter 16 sorts the machine into three groups. Here is where each file lands. Rows marked *(kit's own elaboration)* are files Chapter 16 does not name; the placement is this kit's suggestion, following the chapter's logic.

| File | When you start company two |
|---|---|
| Structure of the kit and every template | **Copy as is** (Chapter 16) |
| Finance and legal playbooks: the finance stack, the monthly close, the compliance calendar and the agent-safety practices | **Copy as is** (Chapter 16): the method copies; the chart of accounts, categorization rules and filing dates are the new company's own |
| Support, sales and marketing playbooks | **Keep, but adapt** (Chapter 16): same patterns, new facts, new offers |
| Golden sets | **Keep, but adapt** (Chapter 16): same method, new examples |
| Voice guide | **Keep, but adapt** (Chapter 16): same principles, new voice |
| Design system | **Keep, but adapt** (Chapter 16): same parts, new colors, type and imagery |
| Agent instructions | **Keep, but adapt** *(kit's own elaboration)*: same structure and escalation rules, new locations and facts |
| Glossary | **Keep, but adapt** *(kit's own elaboration)*: keep the general terms, rewrite the industry ones |
| Lessons log | **Keep, but adapt** *(kit's own elaboration)*: carry the general lessons into shared playbooks; start a fresh log |
| Customer file | **Never copy** (Chapter 16): the new company's own ten conversations |
| Facts sheet | **Never copy** (Chapter 16): every price, policy and promise rewritten from scratch |
| Company brief | **Never copy** *(kit's own elaboration)*: written fresh from the new company's own decision to start |
| Decision log | **Never copy** *(kit's own elaboration)*: start a new one (it may link to portfolio-level decisions) |
| Specifications | **Never copy** *(kit's own elaboration)*: new problems, new specs |
